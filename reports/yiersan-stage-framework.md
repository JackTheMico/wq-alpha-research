# “一二三阶”究竟是什么：定义、设计、实现与应用

## 0. 一句话结论

**“一二三阶”不是三个固定公式，而是一条“复杂度分层生产线”：把 Alpha 的构造拆成可以独立验证的三层——一阶做时序变换（提出信号）、二阶做截面分组（去暴露、重组）、三阶做条件交易（控制何时持仓）。它的价值不在算子本身，而在于“每一层只做一件事、每层都可独立评估”，从而让有限的回测配额产生可归因的结果。**

配套还有两个非官方但被广泛使用的扩展：
- **零阶**（预处理层）：裸字段 → 可直接进入一阶的规范化表达。由帖 `40930298418455` 系统提出。
- **四阶**（组合优化层）：信号融合 / 风险调整 / hump 抑制。由帖 `38451399598615` 提出，社区采用度低于前三阶。

## 1. 先厘清三件事，否则一定走偏

### 1.1 它是“加工方式”，不是“经济逻辑”

这是论坛里最重要的一个否定性判断（帖 `41148880925079`）：

> “1、2、3 阶是「加工方式」；risk59 更缺的是「加工对象选对了没有」。如果第一步就选错了经济含义，后面叠多少阶，往往只是在修饰一个本就不够扎实的……故事。”

推论：阶数增加 ≠ 质量提升。二三阶是**精炼器**，不是**生成器**。一条本身没有经济含义的表达式，跑完三阶只会得到一条过拟合的、还算好看的表达式。

### 1.2 它来自 Alpha Machine 的工程实现，不是金融理论

社区通行的“标准一二三阶”，源头是 `machine_lib` 的三个 factory 函数按序调用（帖 `28126200944919`、`30609613199895`、`33592063316375`）：

| 阶 | factory 函数 | 实质动作 |
|---|---|---|
| 一阶 | `first_order_factory(fields, ts_ops)` | 字段 × 时序算子 的笛卡尔积 |
| 二阶 | `get_group_second_order_factory(exprs, group_ops, region)` | 一阶结果 × 分组算子 |
| 三阶 | `trade_when_factory("trade_when", exprs, region)` | 二阶结果 × 条件模板 |

所以“一二三阶”的边界，本质上就是**这三类算子族的边界**：
`ts_*` → `group_*` → `trade_when`。

理解这一点很关键：不同改版会调整分工（有的把预处理算子放一阶、有的把 rank 放二阶），**边界可以移动，但“单层单职责”这个原则不能破**。

### 1.3 三阶不是必选项

多条证据表明三阶应当谨慎启用：

- 帖 `43735754436247`：有作者“默认自动运行到二阶，三阶保留为手动触发”，因为二阶已能提供足够候选。
- 同帖：有作者逐层拆掉三阶结构后，**Sharpe 从约 0.67 提升到约 0.85**——说明某一层可能纯属噪声。
- 帖 `33953772547607`：Option8/9 数据集上，一、二阶已无一条达到 Regular 标准，作者直接放弃三阶（判断正确，避免了配额浪费）。

## 2. 各阶的准确定义与设计原则

### 零阶：裸字段 → 可加工对象（预处理层）

**目的**：把原始字段变成“量纲统一、缺失可控、时序可算”的对象。论坛经验是**未经预处理直接进一阶，信号产出率显著下降**（帖 `40930298418455`）。

**设计原则**：

1. **先看字段类型，再决定预处理链**（帖 `38451399598615`）：
   - **MATRIX 类**（基本面、季度数据）→ `winsorize(ts_backfill(F, 120), std=4)`，使用率 90%+。
   - **VECTOR 类**（多分析师预测、借贷费率等）→ **必须先用 `vec_*` 聚合为标量**，否则时序算子语义错误。
     - 正确：`ts_delta(vec_avg(oth553_eps_answer_ratio), 20)`
     - 错误：`ts_delta(oth553_eps_answer_ratio, 20)`
   - 7 个聚合算子：`vec_avg`（最常用）、`vec_sum`、`vec_min`、`vec_max`、`vec_count`、`vec_stddev`、`vec_range`。

2. **区分“断粮型 nan”与“真缺型 nan”**（帖 `42184733027991` 高赞回复）：
   - 高频字段偶发缺失 → `ts_backfill` 可补。
   - 低频字段本周期无值 → backfill 反而**抹平季度变化**，制造虚假平滑。
   - 做法：先拉字段的 daily coverage 曲线判断类型，再决定是否回填。

3. **预处理不止“回填+去极值”**：可把字段转为无量纲形式，或先算时序速度、加速度、方差、标准差等统计量，作为一阶的输入。

**关键判据（值得单独记住）**：帖 `43735754436247` 提到，有人**先回测裸字段**看历年是否存在长段无表现，再决定是否进入一阶。这是成本最低的一步——一条裸字段如果一个算子都没套就已经没有 PnL 形状，后面的工作基本是徒劳。

---

### 一阶：单字段时序变换（提出信号）

**目的**：从**单个字段**提取原始信号，把“水平值”转换为“动量 / 均值回归 / 趋势 / 偏离度”。

**标准结构**（帖 `38451399598615`）：

```
winsorize(ts_backfill({field}, 120), std=4)   # 预处理（可归零阶）
  ↓
ts_{operator}(..., window)                     # 时序变换
  ↓
rank / zscore / quantile                       # （可选）末端归一化
```

**设计原则**：

1. **一阶只放核心字段变换，不要把复杂度堆在这里。** 一位回复者（帖 `40930298418455`）的实践总结很典型：
   > “之前爱在 1 阶堆 5–6 个算子，robust 和 PC 都难看；现在把条件放进 3 阶 trade_when、平滑放进 2 阶，1 阶只保留核心字段变换。”

2. **算子选择按族轮换，而非单一模板。** `ts_rank`（压到 0–1，天然抗离群）、`ts_zscore`（标准化）、`ts_delta`（变化量）、`ts_mean`（平滑）、`ts_std_dev`（波动）、`ts_arg_max/min`（时点）、`ts_ir`、`ts_quantile`、`ts_skewness`、`ts_kurtosis` 等 20+ 个。

3. **窗口要覆盖三类时间尺度**，而不是只试一两个：短期 3/5/11/22，中期 66/122/252，长期 504。

4. **一阶产出规模**：每个数据集约 100–300 条。这个量级是有意控制的——一阶太宽，后续阶次的组合爆炸会直接烧光配额。

**失败的处理**：一阶没信号 → 换算子 / 换模板 / **回退到零阶换字段**。最后这个退路最重要，也是最常被忽略的。

---

### 二阶：截面分组操作（去暴露、重组）

**目的**：加入截面标准化或中性化，控制市场、行业、板块、市值效应，让信号变成“组内相对”的判断。

**标准结构**：

```
{一阶表达式}
  ↓
group_{operation}(..., densify({grouping}))
```

**四种主流分组算子**：

| 算子 | 作用 | 何时选 |
|---|---|---|
| `group_neutralize` | 剔除组内均值 | 只想留组内相对偏离 |
| `group_rank` | 组内排名 | 需要截面可比、抗离群 |
| `group_scale` | 组内标准化 | 需要统一量纲 |
| `group_zscore` | 组内 Z-score | 需要标准化偏离度 |

**六种标准分组字段**：`densify(market)` / `sector` / `industry` / `subindustry` / `country`，以及市值分位 `densify(bucket(rank(cap), range='0.1, 1, 0.1'))`。

**设计原则**（重要，反直觉）：

1. **中性化不总是正确选择。** 帖 `41148880925079` 给出明确反例：
   > “借贷紧张在部分行业是常态。`group_neutralize` 能降相关、过检，但也可能把「这个行业就是借不到券」的截面信息抹平。”

   判据：**你要的是“相对同行的溢价”，还是“全市场的稀缺度”？** 前者该 neutralize，后者不该。

2. **区域决定分组方式**：印度偏行业/板块，美国偏市值分位，全球偏国家。

3. **扩展比例**：每个一阶 Alpha 生成 4–6 个二阶变体，总产出 400–1800 条。失控的常见原因是没做去重（见 §4.2）。

---

### 三阶：条件交易逻辑（控制何时持仓）

**目的**：加入市场状态 / 事件驱动条件，控制 Alpha **何时交易、何时空仓**。三阶最主要的实际用途是**压换手、修稳健性**，而不是“造”信号。

**标准结构**：

```
trade_when(condition, {二阶信号}, non_trade_value)
  condition        : 布尔表达式（何时【允许】交易）
  signal           : 二阶 Alpha
  non_trade_value  : 不满足条件时的取值，通常 -1（持有现金）或 abs(returns) > 0.1
```

**条件类型**：成交量条件、价量相关系数、波动率条件、动量条件。

**设计原则（坑最多的一层）**：

1. **condition 的方向极易写反。** 帖 `42065262268567` 的原话：
   > “它要在**允许交易时为真**。我一开始把‘波动率高时’设成不交易，结果趋势真正启动那天恰好被门掉，白白错过主升段。”

   写门控前先明确：**你希望在什么状态下“不动仓”**，然后取反。

2. **三阶适合“带着具体问题”去用**，而不是默认打开：
   - 已有信号是否只在某种状态下有效？
   - 加条件后，换手、收益、覆盖分别发生了什么变化？
   - **必须保留二阶结果作对照**，否则无法判断这一层到底有没有帮助。

3. **降换手优先考虑更简单的杠杆。** `trade_when` 之外还有 `ts_decay_linear`、`clamp`、加长窗口、`ts_target_tvr` 等。注意 decay 的副作用：把窗口从 5 拉到 20，turnover 0.55→0.30 很好看，但 Sharpe 同时 1.3→0.9（帖 `42065262268567`）——**decay 拉太长会把 edge 一起平滑掉**。

---

### 四阶（可选）：组合优化

由帖 `38451399598615` 提出：信号融合、基于回归的风险调整、非线性变换、hump 抑制（`hump`）、动量提取、多因子回归、信息比率优化。

**实践判断**：社区采用度明显低于前三阶。理由是——把优化堆在单个 Alpha 上，收益递减很快；而这些技术更适合放在**组合层**（多 Alpha 融合、相关性剪枝）而不是单条表达式的末端。建议**只在顶级候选上使用**。

## 3. 设计一个“好”的分阶框架：五条硬原则

1. **单层单职责**。一阶只负责“提出信号”，二阶只负责“截面重组”，三阶只负责“何时持仓”。任何一层越界，失败原因就不可归因。

2. **每层必须能独立评估**。每阶跑完都要能回答：“这一层带来了什么增量？”做不到，就该删层（见 §1.3 的 Sharpe 0.67→0.85 案例）。

3. **逐层保留对照样本**。保留上一阶的结果集，不要只留通过筛选的子集。否则“三阶变差”这个结论你永远无法验证。

4. **筛选比例控制在每阶保留 10%–30%**。留太多则下一阶组合爆炸；留太少则好的苗子会被早期噪声误杀。

5. **复杂度上限即过拟合上限**。帖 `28293182637463` 给了一个很实用的工程做法：给算子定义**复杂度权重**（basic 1.0–1.5 / ts 1.5–2.0 / group 类似），设定总复杂度阈值，超阈值的表达式**不进回测**。同时限制同一算子不得出现 3 次及以上，避免 `zscore(zscore(...))` 这类无意义嵌套。

## 4. 如何实现：工程层的关键决策

### 4.1 三种实现形态

| 形态 | 做法 | 适合 |
|---|---|---|
| **官方/社区脚本** | `machine_lib` + `wqb` 包，三个 factory 函数串行 | 快速上手、复现他人经验 |
| **自建流水线** | 自己写字段展开 → 组装 → 批量仿真 → 记录 | 需要精确控制去重、续跑、命名 |
| **LLM 驱动** | LLM 生成表达式 → 校验修复 → 回测 → 反馈回灌 | 大规模探索、跨数据集 |

### 4.2 四个必须解决的工程问题（全是踩过的坑）

**(1) 跨阶污染：下一阶读到的不是你想继续的上一阶结果**

帖 `43735754436247` 记录得非常具体：
> “同一时间跑了多个数据集，只按日期和 region 拉取 Alpha，很容易把它们混在一起；二阶中断后重新查询，已经生成的二阶结果也可能再次混入输入，于是继续套 `group`、套 `trade_when`，表达式越来越长。”

**解法**：跑回测时按 `settings + 阶数` 命名 alpha，下一阶只取 `settings + 上一阶` 的结果。

**(2) 用表达式注释做来源标记与隔离**

帖 `30609613199895` 给出一个零成本方案：在表达式最前面加 `/*T1*/` 形式的注释（**不影响运行，也不计入算子数**），然后在每阶的输入列表上做过滤：

```python
excluded_alpha_expressions = ['/*T', 'trade_when']

# 一阶：跳过自定义模板与已有三阶结构
for alpha in first_order:
    if any(tag in alpha for tag in excluded_alpha_expressions):
        continue
    fo_alpha_expression_list.append((alpha, init_decay))

# 二阶：同样隔离
for expr, decay in fo_layer:
    if any(tag in expr for tag in excluded_alpha_expressions):
        continue
    for alpha in get_group_second_order_factory([expr], group_ops, "USA"):
        so_alpha_list.append((alpha, decay))
```

加 `trade_when` 到排除列表后，就**不会出现“三阶表达式又被二阶 factory 套一层 group”**的经典污染。

**(3) 续跑必须固定本轮输入**

帖 `43735754436247`：
> “只保存‘跑到第几条’还不够：如果重启时重新查询候选，列表已经变化，旧进度就可能失效。”

**解法**：把本轮候选列表的快照（而非游标）落盘，续跑时读快照。

**(4) 缺失值的两种类型要在进一阶前判掉**

见 §2 零阶第 2 条。混入“真缺型”字段是回测配额最大的隐形漏斗。

### 4.3 LLM 驱动的双轮实现（帖 `42184733027991` 的完整方案）

这是目前社区里描述最完整的一套自动化流程，可直接借鉴其骨架：

```
每轮循环：
  1. 参数选择：随机 LLM + 从候选列表挑 neutralization + 轮询数据集
  2. 数据准备：拉该数据集历史反馈（此前轮次表现）+ 字段列表
  3. 生成：LLM 生成 24 条表达式（每条 1–2 个字段）
  4. 修复：括号不匹配、算子参数错误 → 按算子规范自动修
  5. 有效性筛选：字段是否属于该数据集、算子是否合法 → 非法直接丢弃
  6. 批量回测：并发 4，每批 6 条
  7. 异常中断：遇到 CONCURRENT_SIMULATION_LIMIT_EXCEEDED /
     DAILY_SIMULATION_LIMIT_EXCEEDED 立即停止，不浪费调用
  8. 第一轮筛选 → 第二轮定向优化 → 第二轮筛选（更严）
```

**参数（EUR / TOP2500 / delay=1 / INDUSTRY / decay=6）**：

| 项目 | 值 |
|---|---|
| 第一轮筛选 | Sharpe > 1.2，Fitness > 0.8 |
| 第二轮筛选 | Sharpe > 1.3，Fitness > 1.0 |
| 每轮生成 | 24 条 |
| 循环 | 100 轮 |

**社区对其阈值的两条重要修正**：

- 第一轮 1.2 偏宽松。实测很多 Sharpe 1.2–1.3 的 alpha 在 OS 表现很差，**建议提到 1.3 / Fitness 0.9**（高赞回复）。
- 第二轮之前应加**噪声过滤**：检查 yearly return 的变异系数 `CV = 年度收益标准差 / 均值`。`CV > 1.5` 说明收益靠某一年的单一事件撑着，这类 alpha 让 LLM 继续“优化”只会得到 IS 更高、OS 更差的结果。这条建议的实际价值高于阈值微调。

**LLM 方案的致命局限**（帖 `43735754436247` 记录）：
> “AI 会写错字段名、拼出不合适的算子组合，表达式解释得很完整，回测却不理想。”

**修正做法**：不要直接把字段列表丢给 AI 让它生成表达式。先把任务拆成“先按经济含义给字段分组（区分 actual / estimate / level / change / high / low / mean 等角色），再讨论哪些字段适合做差值、比率”，这样人能看清 AI 到底理解了什么，也方便纠正。

## 5. 如何应用：一套可执行的作业顺序

### 5.1 止损优先的顺序（推荐）

帖 `41148880925079` 提出的“与 1-2-3 阶相反的”工作顺序，本质是**把最贵的判断前置到最便宜的位置**：

```
1. 选故事        ← 先专注一条经济机制（如“费率错位”或“利用率×动量”）
2. 定聚合方式    ← VECTOR 字段用哪个 vec_*，决定“你听市场的哪只耳朵”
3. 最简截面/时序对比 ← 先验证 PnL 有没有形状，再考虑上 ts
4. 才考虑二阶    ← 只有确认暴露是噪声而非信号时，才 neutralize
5. 最后才三阶    ← 信号逻辑成立但 turnover / regime 有问题时，用它修剪
```

坛友的对照更直白：
> “很多人路径是：字段 → ts → group → trade_when → 看 Sharpe。”

当阶数框架被当成默认流水线时，**它在替你做字段选择和机制假设**——这是最贵的错误。

### 5.2 回测配额的分配策略

帖 `33601356940823` 给了一个纯经验但很有说服力的数据点（作者 2025 年 1–4 月约 45–50 万次回测、提交 0 个；调整阶间回测数量后，5 月底拿到新人奖励、VF 从 0.27 到 0.5）：

> “跑二阶之前**尽可能把一阶有信号的阿尔法都选上**，三阶同样。虽然回测数量巨大，但对于 vf 只有 0.27 的我来说，提高数量是关键。”

**注意这个说法的边界**：它成立的前提是“一阶已经有信号”。在**信号不足**的阶段，扩量是有效的；在**相关性卡死**的阶段，扩量只会产出更多高相关结果（见 §5.4）。

### 5.3 筛选门槛：区分“能提交”与“该提交”

顾问账号的硬门槛（本项目 `references/checks.md` §5.1.1 权威值，以 `is.checks[].limit` 为准）：

| 指标 | 顾问 D1 | 普通账号参考 |
|---|---|---|
| Sharpe | **> 1.58** | > 1.25 |
| Fitness | **> 1.0** | > 1.0 |
| Turnover | 1%–70% | 1%–70% |

**但“能提交”≠“该提交”**（`checks.md` §5.1.1.1）：平台 `LOW_FITNESS` 的 limit 只有 1.0，而质量线建议 **Fitness ≥ 2.0、Margin ≥ 10‱**。为交而交会把 Value Factor 打到很低，之后交再多也救不回来。

这直接决定了分阶设计的目标函数：**一阶/二阶的筛选阈值应当服务于“找到 Fitness ≥ 2.0 的苗子”，而不是“找到能过 1.58 的”**。用 1.58 当筛选线，会在二阶留下大量注定交不出去的候选。

### 5.4 相关性：阶数无法解决的问题

这是分阶框架最容易让人失望的地方。

- 帖 `33953772547607` 回复区：“用 123 阶代码跑出来的 alpha 平台相关性很高……好不容易跑出来几个都是 0.9 的相关性。”
- 与本项目已验证的结论一致（`README.md` / `SKILL.md`）：**改窗口、改权重、改中性化，几乎创造不出真正低相关的 alpha**。真正决定相关性的是**数据来源与经济逻辑**。

**结论**：相关性必须在**选数据集 / 选故事**阶段解决，而不是指望二阶换个 `group_op`、三阶加个 `trade_when`。三阶换手整形确实会改变 PnL 形态、略微降低相关性，但那是副作用，不是可靠手段。

## 6. 常见失败模式速查

| 现象 | 实际原因 | 处置 |
|---|---|---|
| 一阶一堆 alpha，二阶后信号全无 | 一阶用了无经济含义的算子组合（如对“存量”字段用高换手趋势算子） | 回零阶重新选字段与聚合方式 |
| 三阶后 Sharpe 下降 | 门控条件方向写反，或门掉了信号真正有效的状态 | 检查 `condition` 语义；保留二阶对照 |
| turnover 压不下去 | 在错误的位置压（decay 拉太长反而伤 Sharpe） | 先看流动性档位；`trade_when` 门控方向正确 |
| 表达式越来越长 | 跨阶污染，三阶结果被二阶 factory 重套 | 加 `/*T*/` 标记 + 排除 `trade_when` |
| 大量高相关候选 | 模板同质化 / 数据集已被挖透 | 换数据集或换经济机制，不要调参 |
| 二阶后 Sharpe 变好但 OS 变差 | 年度收益不均匀（CV > 1.5） | 二轮前加噪声过滤 |
| 数据集跑了很多却无 alpha | 该数据集传统 1-2-3 阶不适用（如 Option8/9） | 及时止损换机制，不要扩展同一模板 |
| 表达式合法但回测报错 | delay 迁移后引入了目标 delay 下不可用的字段 | 改 delay 后要复查模板内**额外**使用的字段 |

## 7. 一句话总结

**一二三阶 = 一个把“信号提出 → 截面重组 → 交易门控”解耦的分层实验框架。它的正确用法不是“全部打开然后等出货”，而是：**

1. 零阶把字段处理干净（尤其区分 MATRIX / VECTOR、区分两类 nan）；
2. 一阶只放核心变换，按算子族轮换 + 覆盖三种时间尺度；
3. 二阶只在“确认暴露是噪声”时才 neutralize；
4. 三阶只在“信号成立但换手/regime 有问题”时才启用，且必须留二阶对照；
5. 每层保留对照、每层独立评估，**任何一层不带来增量就删掉它**。

**它服务的是“可归因地花掉回测配额”，不是“自动产出 Alpha”。**
